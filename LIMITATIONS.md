# VoltPulse limitations (honest list)

Everything below reflects real behavior observed on hardware, not guesses. The app prefers
"Not supported by this device" over invented numbers.

## Data sources

- **IOCTL provider (Windows battery driver)** is implemented per the documented contract
  (`IOCTL_BATTERY_QUERY_TAG/INFORMATION/STATUS`, sentinel filtering, tag re-query on battery swap).
  On some OEM drivers - verified on an Acer Nitro ANV15-41 (SIMPLO AP18E7M) - the driver accepts
  these IOCTLs but returns 0 bytes for every information level and rejects status queries. VoltPulse
  detects this (0-byte success = failure) and silently falls back to WMI. On machines with healthy
  drivers the IOCTL provider is the most accurate source.
- **Rate units**: the Windows contract says the rate member is mW, but some firmware reports mA in
  that field. VoltPulse trusts the documented unit; on affected machines the displayed current would
  be off by a factor of the nominal voltage (~12x). No reliable way to auto-detect this exists
  without admin-level EC access.
- **Idle charging**: many drivers report rate 0 / unknown while plugged in but not charging.
  The Live screen shows "Idle" in that case instead of 0 mA.
- **Cycle count** comes from `BatteryCycleCount` (WMI). Firmware frequently reports 0, which
  VoltPulse treats as "not reported" rather than showing a fake 0. The spec's "estimated cycle
  count" (from cumulative energy throughput) is NOT implemented: VoltPulse only knows the energy
  that flowed while it itself was running, which would produce a misleading underestimate. A
  firmware count is shown when present, otherwise the value is hidden.
- **Temperature** exists only if the EC exposes it (roughly half of laptops).
- **Manufacture date** comes from the IOCTL structure with a string fallback; some drivers return
  zeros, which VoltPulse hides.
- **Battery saver state** is not read: the documented path for unpackaged Win32 apps is not
  settled (WinRT-only or undocumented GUIDs). It was consciously skipped rather than guessed.

## Merging and multi-battery

- Batteries from different providers are matched **by enumeration index**. This is exact for the
  common single-battery case and `Win32_Battery`/root\WMI joins are additionally matched by instance
  name with a single-battery fast path; exotic multi-battery setups (3+ batteries, dock batteries)
  may mismatch static facts between batteries.
- The combined view sums capacities and rates and weights the percent by capacity.

## Alerts

- Alerts depend on the data sources above: temperature and drain alerts need a working rate/temperature.
- Toasts are custom in-app popups (bottom-right) plus optional system sound - not Action Center
  notifications, because unpackaged Win32 toast registration is fragile. They appear only while the
  app runs (it is a tray app by design).
- Charger connect/disconnect events rely on the 1 s sampling tick; a very fast plug/unplug
  (< 1 s) can be missed.

## Reports and exports

- The PDF is generated by a small built-in writer (text, bars, one polyline chart). It is plain and
  functional, not a typeset document.
- Chart X axis labels for the HTML/PDF report are relative ("last 24 h"), not absolute timestamps;
  CSV/JSON carry full UTC timestamps.
- Insights analyze the last 7 days of stored sessions/samples only. Fresh installs have no history
  yet, so insights start empty.

## Platform and UI

- Windows 10 1903+ / Windows 11 only (WPF, .NET 8). No Linux/macOS.
- High contrast is supported automatically (system colors take over when Windows high contrast is
  on); there is no custom high-contrast theme editor.
- Localization: English complete; Bengali ships as a proof of the resx pipeline. Only a few strings
  are localized so far - the rest of the UI still reads English.
- The 5 level pills scale against the largest current observed in the session (minimum 5 A window),
  so they calibrate over the first minutes after launch.

## Testing status

- 92 unit tests pass; zero compiler warnings; analyzers on.
- Verified on real hardware: Acer Nitro ANV15-41 (Ryzen 7, Windows 11 build 26300, SIMPLO AP18E7M,
  WMI values identical to `powercfg /batteryreport`).
- **Soak test**: automated soaks were run with `tools\soak.ps1` (working set/CPU/handles): a
  10-minute Debug run (working set stable ~160-174 MB, CPU ~0.85% of one core) and short Release
  runs. The Release runs surfaced a real navigation crash (view construction bug, since fixed) and
  otherwise showed working sets in the same range. **The full 24-hour soak has NOT been run to
  completion as part of this build - run it before shipping (see QA.md).** Memory sits around
  160-175 MB working set (~95-105 MB private), above the original <100 MB aspiration; most of it is
  the WPF+Skia runtime itself.
- DPI/multi-monitor behavior is implemented (PerMonitorV2 manifest, layout scaling) but was not
  physically verified on a multi-monitor rig or at 300% scaling - covered by the QA checklist.
